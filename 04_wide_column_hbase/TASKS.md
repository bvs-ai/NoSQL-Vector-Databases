## Завдання 1. Фільми одного режисера

**Дано:** таблиця `movies` (Row Key — `movie_id`, колонки `info:title`, `info:genre`, `info:year`,
`info:rating`, `meta:director`).

**Що зробити:** напишіть скрипт, який виводить усі фільми режисера, заданого у змінній
`target_director = 'Christopher Nolan'`.

**Спирайтеся на:** [`scripts/2_2_read_movies.py`](scripts/2_2_read_movies.py): пункт 4 — фільтр на клієнті
(`table.scan(columns=...)` + перевірка в Python), пункт 5 — серверний `SingleColumnValueFilter`.
Спробуйте обидва способи й порівняйте, скільки рядків повернув сервер.

**Очікуваний результат:**

```
movie_001: Inception
movie_003: Interstellar
movie_005: The Dark Knight
```

**Питання для самоперевірки:**

1. Скільки рядків ваш скрипт отримав із сервера, щоб знайти ці три фільми? Чому саме стільки?
2. Що станеться з цим запитом на таблиці з 10 мільйонами фільмів?
3. Як змінити Row Key, щоб фільми одного режисера читалися одним range-scan'ом, без перебору всієї таблиці?

## Завдання 2. Row Key для замовлень інтернет-магазину

**Дано:** замовлення у форматі `(customer_id, timestamp, сума, товар)`:

```python
orders = [
    ('cust_100', 1744000001000, 5990, 'Ноутбук'),
    ('cust_200', 1744000002000, 1200, 'Клавіатура'),
    ('cust_100', 1744000003000,  350, 'Килимок'),
    ('cust_300', 1744000004000, 2500, 'Монітор'),
    ('cust_200', 1744000005000,  800, 'Миша'),
    ('cust_100', 1744000006000, 3200, 'Навушники'),
    ('cust_300', 1744000007000,  150, 'Кабель HDMI'),
]
```

**Що зробити:** спроєктуйте Row Key так, щоб:

- замовлення одного покупця лежали поруч;
- останні замовлення читалися першими;
- навантаження на запис розподілялося між регіонами.

Напишіть функцію `make_order_key(customer_id, timestamp) -> bytes`, створіть таблицю `orders_v2`
з Column Family `order`, запишіть у неї всі замовлення (колонки `order:customer`, `order:total`,
`order:product`) і прочитайте всі замовлення `cust_100` одним `scan` з `row_start` / `row_stop`.

**Спирайтеся на:** [`scripts/3_3_logs_good.py`](scripts/3_3_logs_good.py) — сіль і reversed timestamp у ключі логів,
[`scripts/3_4_read_logs.py`](scripts/3_4_read_logs.py) — range-scan за префіксом ключа.
Таблицю `orders_v2` створюйте у своєму скрипті (якщо вже існує — спершу `disable` і `delete`).

**Очікуваний результат** (замовлення `cust_100`, від найсвіжішого):

```
Навушники — 3200 грн.
Килимок — 350 грн.
Ноутбук — 5990 грн.
```

**Питання для самоперевірки:**

1. Виведіть усі ключі таблиці. Чи лежать замовлення одного покупця поруч? Чи йдуть свіжі першими?
2. Чим ваш ключ схожий на ключ логів із частини 3 і чим відрізняється?
3. Що доведеться робити, якщо потрібні замовлення **всіх** покупців за останню годину?

## Завдання 3. Режисер у Row Key (field promotion)

**Дано:** той самий `scripts/movies.csv`. У завданні 1 пошук фільмів режисера перебирав усю таблицю `movies`,
бо Row Key там — `movie_id`.

**Що зробити:** створіть другу таблицю `movies_by_director`, у якій режисер винесений у Row Key:
`director:movie_id` (наприклад, `Christopher Nolan:movie_001`). Завантажте в неї `movies.csv`
(досить колонок `info:movie_id` і `info:title`) і знайдіть фільми Нолана одним `scan` за префіксом ключа
(`row_prefix` або пара `row_start` / `row_stop`).

**Спирайтеся на:** [`scripts/2_1_load_movies.py`](scripts/2_1_load_movies.py) — завантаження CSV через `batch`,
[`scripts/3_4_read_logs.py`](scripts/3_4_read_logs.py) — range-scan за префіксом ключа.
Скрипт, що читає `movies.csv`, запускайте з `scripts/` через `./demo.sh run`, як `2_1_load_movies.py`.

**Очікуваний результат:**

```
Фільми режисера Christopher Nolan (range-scan за префіксом):
movie_001: Inception
movie_003: Interstellar
movie_005: The Dark Knight
(отримано з сервера рядків: 3)
```

**Питання для самоперевірки:**

1. Скільки рядків тепер прочитав сервер? Порівняйте із завданням 1, де результат той самий.
2. Навіщо `:` після імені режисера в префіксі? Що поверне префікс без нього, якщо в таблиці з'явиться режисер
   `Christopher Nolanson`?
3. Чим ми платимо за швидкий пошук? Що треба зробити, коли змінюється назва фільму або додається новий фільм?

## Завдання 4. Версії і TTL разом

**Дано:** товар `sku_42`, ціна якого часто змінюється. Потрібна історія лише кількох останніх цін і лише за
останні 30 секунд (у реальній системі — скажімо, за останній тиждень).

**Що зробити:** створіть таблицю `price_history` з Column Family `price`, у якій одночасно
`max_versions=3` і `time_to_live=30`. Запишіть у `price:value` три ціни (`1000`, `1100`, `950`), зачекайте 20 секунд
і запишіть ще дві (`1200`, `1050`). Прочитайте всі версії комірки одразу, а потім ще раз через 15 секунд.

**Спирайтеся на:** [`scripts/4_1_versions_write.py`](scripts/4_1_versions_write.py) — запис кількох версій,
[`scripts/4_2_versions_read.py`](scripts/4_2_versions_read.py) — `table.cells(..., versions=10, include_timestamp=True)`,
[`scripts/4_3_ttl.py`](scripts/4_3_ttl.py) — TTL на Column Family і `time.sleep`.

**Очікуваний результат** (час буде ваш):

```
Одразу після запису: версій 3
  12:31:15 → 1050
  12:31:15 → 1200
  12:30:54 → 950

Через 15 с: версій 2
  12:31:15 → 1050
  12:31:15 → 1200
```

**Питання для самоперевірки:**

1. Куди поділися `1000` і `1100` уже в першому читанні? А `950` — у другому? Який механізм спрацював у кожному випадку?
2. Чи лежать ці значення фізично на диску? Коли вони зникнуть насправді?
3. Повернімося до інтернет-магазину. Чи потрібні TTL і версії таблиці `orders`? А таблиці з сесіями користувачів?
   Для кожної вирішіть: скільки версій, який TTL (або без TTL) і чому.
